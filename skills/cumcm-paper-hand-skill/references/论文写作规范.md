### 一、论文整体结构骨架

**先把整篇论文的骨搭建起来**

数模论文的标准骨架（按出现顺序）：

```
摘要 → 问题重述 → 问题分析 → 模型假设 → 符号说明 → 模型建立与求解 → 模型评价与推广 → 参考文献 → 附录
```

>  **核心逻辑链**：每个子问题都要形成"**问题分析 → 模型建立 → 模型求解 → 结果分析 → 小结**"的闭环。
> 
>- **最重要：叙事逻辑**： 不要出现问题重述的时候1，2，3问题都写了，但是每一问都像是一个独立的文章，前面的模型和后面的模型没有一点承接。比较好的方法是提前梳理：问题二是否使用了问题一的模型，问题三是在问题一的基础上扩展，还是重新建立了新的模型，前一问的输出是否有可能变为后一问的输入，后一问是否能反过来验证前一问的合理性。

### 二、逐节写法精要

#### 1. 问题重述 —— 展示你的理解深度

- **需要逐个小问展开说明**：需要每一个小问单独叙事
- **用自己的语言复述**： 不可大段照抄原题文字，把题目中的长背景压缩掉
- **把每一个小问题整理为明确的数学任务**：不要只写“根据附件数据建立模型并进行预测”，而是写“基于附件中的数据监测分析，分析各个指标与目标变量之间的关系，建立预测模型，并利用给定数据计算未来时刻的预测结果“。问题重述科研适当改变表达顺序而是帮助读者识别：**题目的研究对象**，**已知条件**，**核心矛盾**和**每一问的任务**。

  
#### 2. 问题分析 —— 要写建模的方案

- **需要逐个小问展开说明**：需要每一个小问单独叙事
- **推荐顺序**： 题目要求 → 关键难点 → 数据或者变量特征 → 总体建模思路 → 求解和检验方法
- **注意**： 问题分析不需要提前展开公式，也不能只叙述“我们建立某某模型解决某某问题”，而是要解释为什么这个问题适用于该模型。例如选择回归模型，只好啊要说明变量之间存在什么样子的相关趋势；选择聚类模型，要说明为什么对样本进行分类来选择优化模型，要指出目标函数，决策变量和主要约束分别是什么
- **总结**：该部分需要让人知道我们的每一问准备：处理什么数据，分析什么关系，建立什么类型的模型，使用什么方法求解，通过什么指标评价结果。 
  
#### 3. 模型假设 —— 不是简单的忽略次要因素

- 假设要**合理且必要**：每条假设都要解释"为什么可以这样假设"。
- 数量：**5–10 条**为宜。太少 → 显得考虑不周全；太多 → 模型太特殊、适用面窄。
- 假设要**覆盖关键简化**：如忽略次要因素、近似处理、理想化条件等。
- 末尾加过渡句："以上假设的合理性将在模型检验部分进一步验证。"
- 做有承接的假设：假设一旦写出，**后文最好能够找到它对应的模型依据**。

#### 4. 符号说明 —— 只放真正重要的因素

- 使用**三线表**格式：符号 | 含义 | 单位（如有）。
- **全文符号统一**：同一符号不在不同地方表示不同含义。
- 优先使用学科惯例符号（$\theta$ 角度、$\lambda$ 比率/特征值、$\rho$ 密度等）。
- 符号表放在模型建立之前，方便评阅人随时查阅。

#### 5. 模型建立与求解 —— 论文的核心（占篇幅最大）

这是论文最重要的部分，按子问题逐一展开。

##### 5.1 每个子问题的标准写法

每个子问题都建议按以下结构组织：

问题目标 → 数据处理 → 变量定义 → 模型原理 → 模型建立 → 参数确认 → 算法求解 → 结果呈现 → 结果检验 → 本问结论。

>  **"每个子问题末尾加一个小结"** 是非常好的做法：让评阅人读完每个子问题都能立刻抓住你的贡献，而不需要翻回摘要。比如：
“综上，本文建立了....模型，求得....，模型在验证集上的指标为....，说明模型具有....，所得结果将在问题X作为....使用”

##### 5.2 建模过程的叙述技巧

- **公式不得直接给出**：每个重要公式前面要有引导文字（"由…定律/原理可得""考虑到…因素，引入…"）。公式提出前要说明为什么要建立这个关系，公式中阐明每个变量得含义，公式后要给出这个公式能计算什么，下一步该怎么使用
- **推导过程**：关键推导步骤放在正文，冗长的推导放附录，正文中注明"详细推导见附录A"。
- **"先文字，后公式，再解释"** 的三段式：先用文字说思路 → 给出数学公式 → 解释公式每一项的含义。
- **标准性**：例如优化问题要给出最后优化的标准型，求解问题要写清楚求解标准型
- **避免写成代码说明书**：要在数学层面讲清楚你在做什么，不要写"我们调用了 xxx 函数，输入了 xxx"。

##### 5.3 结果呈现技巧

- **图和表是评阅人的第一关注点**：每张图/表都要做到"看图说话"——不看正文也能大致理解。
- 图/表编号 + 标题：如"图5 三种策略下的成本对比"。
- 表格优先用三线表。
- **关键数据加粗或高亮**：在对比表中，最优值加粗，让评阅人一眼看到。
- **每个图表都要在正文中被引用和讨论**：不可放一张图却不分析它说明了什么。
- **结果要与建模呼应**：分析结果时回到模型假设，说明结果是否符合预期、是否验证了模型的合理性。

##### 5.4 过渡与衔接

- 子问题之间要有**承上启下的过渡句**。如："问题二在问题一的基础上进一步考虑了…因素，因此我们在模型一的基础上做了如下改进…"
- 体现**模型之间的递进关系**（后面的模型如何在前面的基础上改进/扩展）。

##### 5.5 算法部分怎样写清楚

- 一般使用伪代码，复杂算法可以采用流程图。但是流程图不能是：输入数据 → 建立模型 → 运行程序 → 输出结果。一个有效的流程图应该要体现算法内部真正重要的步骤，例如初始化，迭代更新，适应度计算约束判断和终止条件。

##### 5.6 数据预处理方面注意

- 不可以直接写“首先对附件文件进行了预处理”。比较完整的数据至少要交代：原始的数据中存在什么问题，采用了什么方法，方法中的关键参数，参数为什么这么选，处理后保留了什么特征，是否对处理效果进行了展示
  
##### 5.7 要证明结果可信

- 不能直接写：“最终结果如图所示”。至少还要解释：结果呈现出什么样的趋势；是否复合世界问题背景；不同方法的结果是否一致；误差是否在合理的范围内；模型对参数的变化是否敏感。
- 常见的检验方法包括：误差分析，残差分析，交叉验证，敏感性分析，不同模型对比，与真实值或已知结论比较。
- 对极端结果进行合理性验证：不一定没电都要做，但是必须根据模型选择真正适用的检验方法
- **强调**：正文必须直接回答题目


##### 5.8 写模型建立前的一些可以加的叙事
- 统计问题是否可以根据数据趋势或者图像先对数据进行分析从而得出为什么要如此建立模型
- 可否先叙事背景或者其他必要性措施让读者更容易读懂我们的建模
  

#### 6. 摘要最后写
- **浓缩最具价值的信息**：用了什么模型，使用什么算法求解，得到了什么关键结果，采用了什么方法验证，最终结论如何，每一问可以按照这个句式整理：针对....问题，首先....，随后建立....模型，采用.....算法求解，得到....结果；通过.....检验,表明模型....
- **不要泛泛的写结果良好，具有一定可行性**: 直接写数值结果，评价指标

#### 7. 模型评价与推广
- 从"模型的优点 / 模型的缺点 / 模型的改进方向 / 模型的应用推广"四个维度展开。
- 缺点要真实具体（如"计算复杂度高，大规模数据下求解时间超过 X 分钟"），并给出可行的改进思路。
- 推广要结合本题背景向外延伸，不说空话。

#### 8. 参考文献 —— 必须真实、充足、高质量（不得糊弄）

- **必须真实**：用网络搜索逐一核实每篇文献（作者、题名、期刊/会议、年份、卷(期)、页码），禁止凭记忆编造文献。这是红线：评阅人查到一篇假文献，整篇论文的可信度都会崩塌。
- **数量充足**：一般 8–15 篇。太少显得积累不足；覆盖四个方面——模型理论出处、算法出处、领域背景、对比方法。
- **质量优先**：优先期刊论文、学位论文、权威专著，避免与正文无关的文献凑数；每篇文献必须与正文内容强相关。
- 只列正文真正引用的文献，按引用顺序编号，正文标注 [1][2]；格式统一（国赛用 [1] 作者. 题名[J]. 期刊,年,卷(期):页码。 的格式；美赛按标准期刊格式）。
- 可以用 `ref/` 里优秀论文的参考文献列表作为格式参考，但**引用内容必须真实**。

#### 9. 附录 —— 评阅人核查工作真实性的地方（很重要）

- **附录是评阅人验证"这些工作你确实做了"的地方，不是凑页数的**。放：冗长推导、核心程序源码、大表格、原始数据的部分展示。
- 每条附录有编号与标题，正文中注明"详见附录A"；附录与正文标注一一对应，不允许正文没提而附录凭空出现内容。
- **内容必须真实对应正文**：附录推导与正文公式一致、附录代码可运行且确实是求解所用代码（删掉无关调试代码、加必要注释）、附录表格数据与正文数值同源。
- 附录缺失或糊弄，会让评阅人对正文的所有结果产生怀疑。
